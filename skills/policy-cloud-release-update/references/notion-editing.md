# Notionを編集するときの実務メモ

操作方法は、その実行環境のツール説明と現在の画面を優先する。以下は成功条件と、今回の作業から得た注意点。

## 編集対象を小さくする

- 現在のページと対象ブロックを読み、変更する見出し・段落・画像を特定する。長い調査後は編集直前に再読する。
- ページ全体の置換を避け、対象ブロックの更新・追加を使う。ユーザーが並行して文章や画像を変更している可能性を考慮する。
- 見出し階層、太字、トグル、リンクを維持する。リッチテキスト段落へプレーンテキストを入れ直すとリンクが失われることがあるため、変更後にリンク先も確認する。

## 画像

- GitHubの添付画像は認証が必要な場合がある。認証済みのGitHub手段で原本を取得し、期限付きURLを恒久的な出典リンクとして使わない。
- Notionへアップロードするか、適切な掲載済み画像ブロックをコピーする。画像の置換と追加を混同しない。
- 使用可能な場合は、ブラウザのファイルアップロード、画像のクリップボード貼り付け、既存画像ブロックのコピーが候補になる。特定手段の失敗からアクセス権や拡張機能設定を勝手に変更しない。
- 貼り付け直後に空の埋め込みブロックが見えることがある。表示完了を確認してから、失敗かどうかを判断する。再試行の前に重複がないか確認する。
- 画像にキャプションを付ける。製品画面の外に書けば、画像を加工せずに開発中・試験提供などの状態を伝えられる。

## ブラウザ操作が必要な場合

- 利用可能なブラウザツールのドキュメントに従い、現在のDOM・アクセシビリティ情報をもとに操作する。過去のタブID・ブロック順・座標は再利用しない。
- Notionではブラウザ上の文字選択とブロック選択が一致しないことがある。貼り付け後に、置換のつもりが末尾への追記になっていないか確認する。
- 同じ方法で変化がない場合は状態を読み直し、別の許可された方法に切り替える。改善の根拠がない再試行を繰り返さず、本文など独立して進められる作業を先に完成する。
- ログイン・本人確認が必要なときは、その環境の認証手順に従う。パスキーなど利用者の操作が必要な部分だけ引き継ぐ。過去のログイン済み状態を前提にしない。

## 終了条件

- 対象の文章と画像が実際に表示され、保存されている。
- 公開状態・日付・限定範囲が根拠と一致する。
- 出典リンクとBacklogリンクが正しく、準備中表記と画像の有無が矛盾しない。
- 失敗時の空ブロックや重複画像がなく、過去の節やユーザーの追記が残っている。

今回の作業から継承するのは判断と確認方法であり、特定の日付・Issueの状態・スクリーンショットを次回の最新情報として再利用しない。
